# dev/: инструменты разработчика

Здесь лежит то, что нужно при разработке, но не попадает на сайт.

| Файл | Что делает |
|---|---|
| `check-modules.mjs` | Проверяет все модули в `src/`: нет ли забытых `import`, несуществующих экспортов и циклических зависимостей. Запускать после любого переноса кода по файлам. |
| `smoke-effects.js` | Дымовой тест режима «Эффекты» в браузере: входит в режим, включает и выключает каждый эффект, выходит в редактор и возвращается. Собирает ошибки, долгие задачи, блокировки WebGL и самые долгие кадры. |
| `effects-inventory.mjs` | Собирает `docs/effects-inventory.md`: таблицу эффектов, значений кадра и размеров шейдеров (`node dev/effects-inventory.mjs > docs/effects-inventory.md`). |
| `webgpu-proto.html` / `.js` | Стенд сравнения WebGL и WebGPU: сравнение картинок попиксельно (`__proto.compare`, `fuzz`, `postCompare` для пост-обработки, `moshCompare` для датамоша), скорость, холодная сборка шейдеров. Запуск и результаты: `docs/webgpu-prototype-report.md`. |
| `gen-wgsl.mjs`, `glsl2wgsl.mjs` | Переводчик GLSL → WGSL и генератор `src/effects/shaders/wgsl/generated/*` из боевых GLSL-шейдеров. После любой правки GLSL: `node dev/gen-wgsl.mjs`. |
| `compare-backends.js` | Сравнение WebGPU и WebGL на одном кадре: каждый эффект рисуется обоими путями подряд из одного состояния, картинки сравниваются попиксельно; видно и то, не уходил ли кадр в WebGL. Запуск в консоли приложения с `?gpu=1` (в режиме «Эффекты»): подключить скрипт, затем `await __compare.run()`. |
| `baseline.json` | Эталонные результаты дымового теста (с чем сравнивать после правок). |

## Сборка и запуск

```bash
python build.py          # собрать assets/app.js
python build.py --web    # собрать web/ (версия для публикации)
python -m http.server 8765   # открыть http://localhost:8765/index.html
```

После любой правки в `src/` нужно пересобрать оба варианта: `index.html` читает `assets/app.js`, а сайт на хостинге берёт `web/`.

## Проверка модулей

```bash
npm i --no-save acorn            # один раз (парсер JS)
node dev/check-modules.mjs
```

Если `acorn` лежит не в проекте: `ACORN=/путь/к/acorn node dev/check-modules.mjs`.
Ожидаемый результат: `Проверено модулей: N. Проблем нет.`

## Дымовой тест эффектов

1. Запустить локальный сервер и открыть приложение в Chrome.
2. В консоли браузера выполнить:
   ```js
   const s = document.createElement('script'); s.src = '/dev/smoke-effects.js'; document.head.appendChild(s);
   ```
   Для проверки WebGPU-пути открыть приложение с `?gpu=1`: в отчёте появится `backend: {kind: 'webgpu', frames: {gpu, gl}}`.
3. Подождать около 1,5 минуты. Пока `window.__smoke.done` равно `false`, тест идёт.
4. Посмотреть `window.__smoke.report`:
   - `problems` должен быть пустым;
   - `slowSteps`: шаги с долгими задачами (>150 мс) или блокировками WebGL. Допустим только вход в редактор (~100 мс);
   - `worstFrame`: самый долгий кадр за весь тест. Первое значение около 1000 мс это кадр при загрузке страницы, не ошибка.

Тест нужно гонять на машине с настоящей видеокартой (не в программном рендере).
Если WebGL вдруг отключился (в консоли `GL_VENDOR = Disabled`), Chrome убил видеопроцесс: перезапустите браузер.
