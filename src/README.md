# Устройство исходного кода (`src/`)

Код разложен по смыслу: каждая папка отвечает за один кусок приложения. Все файлы это ES-модули, `build.py` собирает их в один `assets/app.js`.

```

## Режим «Эффекты» (`src/effects/`)

Главная идея: **движок считает, что рисовать; рендер-движок решает, как это попадёт на экран.** Это нужно, чтобы рядом с WebGL можно было добавить WebGPU и не переписывать всё остальное.

```

  engine/                 движок эффектов (не знает про WebGL)
    index.js              класс EffectsEngine: конструктор, вход и выход из режима
    mixin.js              подмешивает методы частей в класс
    frames.js             раскадровка видео (кольцо кадров, общее с «Шлейфом движения»)
    chrono.js             «Шлейф движения»: выделенный объект оставляет шлейф прошлых кадров

    recording.js          запись видео: прозрачные холсты сцены собираются на непрозрачном с фоном, точный размер кадра, покадровая запись таймлайна

### Как устроен класс `EffectsEngine`

Класс получился очень большим, поэтому его методы разнесены по файлам («частям»). Каждый файл содержит класс вида `FramesPart` с методами, а `engine/index.js` в конце подмешивает их все в `EffectsEngine` через `mixin()`. Для остального кода ничего не изменилось: это по-прежнему один класс с теми же методами. Если один метод случайно окажется в двух файлах, `mixin()` выбросит ошибку при запуске.

### Правила для шейдеров WebGL (важно)

На Windows видеодрайвер собирает шейдеры очень долго, и из-за этого раньше замирал браузер. Поэтому:

1. Любой новый объект со своим шейдером должен собираться **заранее и в фоне**, а до готовности быть скрыт (см. `_gate` в `render/webgl/shader-cache.js`).
2. Нельзя собирать «полный» шейдер со всеми эффектами сразу: на слабых видеокартах Chrome убивает видеопроцесс.
3. Шейдер урезается под включённые эффекты (`specialize.js`) и сжимается обратно, когда эффект долго выключен.

### Рендер-движок WebGPU

**Выбор** (`render/select.js`): адрес с `?gpu=1` / `?gpu=0` (или `localStorage['pointbloom.gpu']`) важнее всего, дальше настройка «Движок отрисовки» (Авто / WebGPU / WebGL) в разделе «Производительность» панели эффектов. «Авто» берёт WebGPU на Windows и Linux (там WebGL подвисал на сборке шейдеров), на Mac остаётся WebGL. Программный адаптер WebGPU (без видеокарты) в «Авто» не берётся. Если WebGPU не заработал (нет адаптера, не собрался шейдер, потеряно устройство), в `localStorage['pointbloom.gpu.bad']` ставится пометка и «Авто» больше его не пробует, а кадры тут же идут через WebGL.

**Устройство.** Сцена редактора (сетка, фон) по-прежнему рисуется WebGL на основном холсте; облако точек и пост-обработка рисуются WebGPU на втором холсте поверх (`webgpu-backend.js`). На WebGPU работает всё: облако со всеми эффектами (в том числе «Экран», «Слит-скан», «Пиксельная сортировка», «Рост на ритме»), «Тень на стене» (вариант расчёта SHADOW и `webgpu-surface.js`), шлейф-копии, связи и осциллограф (`webgpu-mesh.js`), шлейф персонажа (`webgpu-trail.js`), раскадровка и «герой» (видео поверх блока), обратная связь, свечение, аберрация, датамош (`webgpu-post.js`), все тональные компрессии из настроек (нет, Neutral, ACES, AgX), рамки слежения (положения точек читаются из прохода расчёта). Шейдеры порождает `dev/gen-wgsl.mjs` из тех же GLSL, что у WebGL (после правки GLSL: `node dev/gen-wgsl.mjs`; на Node 20 с флагом `--experimental-detect-module`). Проверить, что картинка совпадает с WebGL: `dev/compare-backends.js`.

**Буферы.** Проходу расчёта хватает 8 буферов хранения (минимум, который WebGPU гарантирует любой видеокарте): данные точек лежат парами в четырёх буферах (`inP0..inP3`), у линий свои привязки по числу атрибутов. Раньше нужно было 11, и на многих видеокартах (Mac, часть встроенных) WebGPU не включался.

**Запись и снимки.** Холст WebGL и холст WebGPU склеиваются в составной (`viewport.captureCanvas()`, `fxCompose`): с него идут запись видео и GIF; скриншот дорисовывает слой WebGPU сам.

**Запасной путь.** Кадр целиком идёт через WebGL, только если WebGPU не справился: не собрался шейдер какого-то объекта, потеряно устройство (`WebGPUBackend._glOnly`). Шейдеры WebGL пока WebGPU рисует, не собираются (`engine._glDormant`): именно их сборка вызывала подвисания на Windows. Нужен WebGL-объект, и WebGL «просыпается» (`wakeGl`): шейдеры собираются в фоне, кадры тем временем идут через WebGPU, а когда всё готово, кадр переключается на WebGL.

**Первое включение эффекта.** Шейдеры связей, осциллографа и «героя» собираются по первому требованию и асинхронно (в Chrome на Windows это несколько секунд в видеопроцессе, главный поток не занят), пока собираются, объект просто не виден.
