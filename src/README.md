# Устройство исходного кода (`src/`)

Код разложен по смыслу: каждая папка отвечает за один кусок приложения. Все файлы это ES-модули, `build.py` собирает их в один `assets/app.js`.

```

    demo.js               демо-модель и демо-анимация
    device-guard.js       проверка, что видеокарта и браузер подходят
  core/                   общие мелочи, от которых зависят все

    history.js            отмена и повтор в редакторе

  scene/                  3D-сцена редактора

## Режим «Эффекты» (`src/effects/`)

Главная идея: **движок считает, что рисовать; рендер-движок решает, как это попадёт на экран.** Это нужно, чтобы рядом с WebGL можно было добавить WebGPU и не переписывать всё остальное.

```

  engine/                 движок эффектов (не знает про WebGL)
    index.js              класс EffectsEngine: конструктор, вход и выход из режима
    mixin.js              подмешивает методы частей в класс
    frames.js             раскадровка видео
    keyframes.js          анимация по ключам
    source.js             что показывает облако: модель, фото, видео, формы, морфинг
    links.js tools.js tracking.js history.js scope-trail.js
    depth.js audio.js interaction.js loop.js recording.js
  state/                  данные: список эффектов (layers), справочники (options), начальное состояние (defaults)
  shapes/                 готовые формы и подготовка облака
  audio/                  встроенный синтезатор
  input/                  руки, камера движения, карта глубины
  frames/                 блок кадров раскадровки
  ui/                     панель эффектов, превью, HUD

    backend.js            контракт рендер-движка (RenderBackend)
    select.js             выбор движка: WebGL по умолчанию, WebGPU по адресу с ?gpu=1
    shared/               данные кадра (frame-uniforms.js): общие для любого рендера
    webgl/                реализация на WebGL
      webgl-backend.js    выходная стадия: пост-обработка, переключение вывода
      scene-build.js      объекты сцены: точки, призраки, линии
      shader-cache.js     урезание шейдера под включённые эффекты, фоновая сборка
      specialize.js post-pipeline.js programs.js textures.js
    webgpu/               реализация на WebGPU (включается вручную: адрес с ?gpu=1, см. ниже)

      frame-layout.js     раскладка значений кадра в буфере

### Как устроен класс `EffectsEngine`

Класс получился очень большим, поэтому его методы разнесены по файлам («частям»). Каждый файл содержит класс вида `FramesPart` с методами, а `engine/index.js` в конце подмешивает их все в `EffectsEngine` через `mixin()`. Для остального кода ничего не изменилось: это по-прежнему один класс с теми же методами. Если один метод случайно окажется в двух файлах, `mixin()` выбросит ошибку при запуске.

### Правила для шейдеров WebGL (важно)

На Windows видеодрайвер собирает шейдеры очень долго, и из-за этого раньше замирал браузер. Поэтому:

1. Любой новый объект со своим шейдером должен собираться **заранее и в фоне**, а до готовности быть скрыт (см. `_gate` в `render/webgl/shader-cache.js`).
2. Нельзя собирать «полный» шейдер со всеми эффектами сразу: на слабых видеокартах Chrome убивает видеопроцесс.
3. Шейдер урезается под включённые эффекты (`specialize.js`) и сжимается обратно, когда эффект долго выключен.

### Рендер-движок WebGPU

Включение: открыть приложение с `?gpu=1` в адресе (или `localStorage['pointbloom.gpu'] = '1'`). Без видеокарты с WebGPU автоматически остаётся WebGL.

Сцена редактора (сетка, фон) по-прежнему рисуется WebGL на основном холсте; облако точек и пост-обработка рисуются WebGPU на втором холсте поверх. То, что на WebGPU ещё не перенесено, рисует WebGL, и пока такой объект виден, кадр целиком идёт старым путём (`WebGPUBackend._glOnly`):

- связи, осциллограф, шлейф-линии («след»), раскадровка и её «герой» (видео поверх блока);
- тон-карта, отличная от Neutral;
- запись видео и экспорт кадра (они читают основной холст, поэтому пока не видят облако WebGPU).

Пока облако рисует WebGPU, шейдеры WebGL не собираются (`engine._glDormant`): именно их сборка вызывала подвисания на Windows. Когда появляется объект, который умеет рисовать только WebGL, WebGL «просыпается» (`wakeGl`): шейдеры собираются в фоне, кадры тем временем идут через WebGPU без недостающего объекта, а когда всё готово, кадр переключается на WebGL.
